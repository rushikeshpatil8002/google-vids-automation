# 06 — Milestones

Work through the milestones in order. Each step follows: **build → test → commit → tick the box** (continuous mode, CLAUDE.md rule 1). "Gen budget" is the most live Vids generations a step may use; the budgets are pre-approved.

Legend: 🧑 = developer does it by hand · 🤖 = Claude Code does it

---

## M1 — Feasibility (first; total gen budget ≤ 5)

**Goal:** verify the real Google Vids behavior before building the full app (F1–F6).

- [x] **1.1 🧑 Environment**
  - Install Python 3.11+, Chrome stable, Git, and Claude Code.
  - `python -m venv .venv`, activate it, `pip install -r requirements.txt`, `cp config.example.json config.json`, `git init`, first commit.
  - Gen budget 0.
- [x] **1.2 🤖 Minimal browser tooling**
  - Build `automation/config.py`, `automation/platform_utils.py` (Chrome path detection), `automation/browser.py` (attach/launch, CDP download dir), `app.py --login` (only the CLI login path, no Flask routes yet), and `tools/ui_probe.py` (§9 of 05).
  - Unit-test config loading and Chrome path detection.
  - Gen budget 0.
- [x] **1.3 🧑 Sign in**
  - Run `python app.py --login`, sign in to Google, and open Vids.
  - Record in the feasibility report: account type, UI language, Chrome version, and whether sign-in worked in attach mode. If not, try `browser.mode=launch` and record that.
  - Gen budget 0.
- [x] **1.4 🧑+🤖 Manual walkthrough with probe**
  - The developer does a **single-part** flow by hand: new blank project → Generate video → upload `input/Sample_Project/part_01/reference.png` → paste the part_01 script → Generate → wait → insert/place → download.
  - Run `python tools/ui_probe.py` and capture a snapshot at every screen change.
  - Then repeat with **2 parts in one project** (add a scene), followed by a full-project download/export.
  - Record any limit or quota text seen, and the prompt character limit and image count limit if the UI shows them.
  - Gen budget 3.
- [x] **1.5 🤖 Selector extraction**
  - Read the `docs/feasibility/raw/*/a11y.json` files.
  - Fill `automation/vids_selectors.json`: elements with fallbacks, text patterns, `capabilities`, `_meta`.
  - Mark fragile selectors.
  - Gen budget 0.
- [x] **1.6 🤖 Scripted feasibility run**
  - Write `tools/feasibility_run.py`: one single-part flow using only the selector file, attach mode, CDP download → staging → `verify_video`. It prints PASS/FAIL per step.
  - The developer runs it once.
  - Gen budget 1.
- [x] **1.7 🤖 Feasibility report**
  - Complete `docs/07_FEASIBILITY_REPORT.md`: F1–F6, step classification table, screenshots copied to `docs/feasibility/` (redact the email if visible), DEC-02 branch selected, go/no-go.
  - Update `CLAUDE.md` status.
- [x] **1.8 🧑 Send to client**
  - Send the report summary to the client.
  - **No-go** (e.g. generation unavailable, or downloads impossible): stop and renegotiate scope.
  - **Go**: continue to M2.

**Exit criteria:** every `capabilities` value is non-null, every required selector is verified or `not_applicable`, the report is complete, and the developer approves.
